# 电视剧 TMDb 元数据替换（Phase 3A）

电视剧工作台支持安全的匹配与远端数据预览。选择候选后，远端信息立即替换当前电视剧元数据，并立即原子写入对应 Kodi NFO；本地图片不会被此操作修改。

## 操作流程

1. 扫描数据源并在“电视剧”中选择一部已索引的剧。
2. 点击“匹配电视剧”；默认以剧目录名称和识别到的年份搜索 TMDb，也可手动修改查询。
3. 明确选择一个候选。系统请求剧详情，并只请求本地已经发现的季。
4. 标题、评分、演员和已匹配集的标题/时长立即替换为所选 TMDb 元数据；随后写入 `tvshow.nfo`、每季的 `season.nfo` 和每个媒体文件对应的单集 NFO。

当前元数据保存在 SQLite 的 `tv_metadata` 与 `tv_episode_metadata`。每次选择候选都会完整替换这两张表中该剧的现有元数据，并以同目录临时文件和原子重命名替换已有普通 NFO。目标路径、软链接、文件类型和媒体源权限会在写入前重新校验，且每项写入均保留审计记录。图片和视频文件不会创建、下载或覆盖。

尚未选择 TMDb 元数据时，工作台会读取现有的 `tvshow.nfo` 和单集 `episodedetails` NFO 来显示标题、剧情、评分、演员及单集标题，并在 SQLite 尚无记录时缓存该本地读取结果；工作台也会只读展示剧目录和已发现季目录中的 JPEG、PNG、WebP 图片。

本地剧级 `poster` / `folder` / `cover` 与 `fanart` / `backdrop` / `landscape` 会优先用于工作台和目录缩略图；所有本地图片均通过已登录会话下的受限资产地址读取，不会暴露容器或宿主机绝对路径。

## 季与单集工作流

电视剧目录使用可展开的“剧 → 季 → 集”树形列表。选择剧、某一季或一个文件时，右侧工作台会切换为该对象的信息与文件范围；季显示其已索引单集，单集显示其编号、标题、剧情和单文件路径。

所有工作台标签都遵循该范围：图片资源只列出剧目录、所选季目录或所选单集同名的本地图片；文件审计只列出所选范围内的视频与 sidecar；NFO 原文读取对应的 `tvshow.nfo`、`season.nfo` 或单集 NFO。演职员仅属于剧级 Kodi NFO 字段，因此选择季或单集时会显示该范围没有独立演职员，而不会错误展示整剧演员表。

首次仍需在剧层级匹配 TMDb，以建立剧的 TMDb ID。其后可以在季或单集层级点击“刮削”：

- 季刮削只请求该季，并仅替换 SQLite 中这一季的集元数据，随后原子写入该季的 `season.nfo` 与其单集 NFO。
- 单集刮削只请求所属季以定位该集，并仅替换这一个 SQLite 条目与这一个单集 NFO。
- 不会改动剧信息、其他季/集、图片或视频文件。

每次上述 NFO 写入都会先创建受校验的写入计划，复用同一套临时文件、原子替换、路径白名单和审计机制；在选择该剧的 TMDb 候选后则保留既有的整剧立即写入行为。

## 匹配范围

- 支持扫描已识别的 `S01E02`、`1x02`、连续多集文件及 Season 0。
- 只获取本地存在季的远端单集数据，避免把未下载的官方剧集误写进本地状态。
- 当前一个多集文件的显示标题以其第一个集号匹配；完整的多集 NFO 写入与缺集报告属于 Phase 3B。

## 诊断日志

正常流程依次可见：

- `TMDb TV search started/completed`
- `TMDb TV metadata replacement started/completed`
- `TMDb TV details mapped`

日志只记录内部 ID、数量和状态，不记录 API Key 或代理凭证。
